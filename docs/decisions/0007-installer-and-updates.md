# ADR 0007: Installer und Updates

- Status: teilweise entschieden. **Entscheidungen des Nutzers (2026-11-20, WP-10):** automatisch nach Updates suchen wie FerretSharp (dort ADR 0024, WP-32 mit Nachträgen) – beim Start und während RepoBoard läuft (Nie / Stündlich / Alle 4 Stunden, Standard / Täglich), abschaltbar, „Jetzt prüfen“; nur melden, Herunterladen und Neustart erst nach Klick; Quelle sind die GitHub-Releases ohne Token. Dazu **eine Windows-Benachrichtigung je neuer Version**. **Vorschlag (nicht bestätigt):** die Technik unten.
- Datum: 2026-11-20

## Kontext

Bisher gab es RepoBoard nur als Build (`dotnet run`, `dotnet publish`). Ein Tag markierte eine Version, aber niemand bekam sie. FerretSharp hat dasselbe Problem mit Velopack gelöst (ADR 0024 dort) und es seit 3.29.0 im Einsatz; RepoBoard übernimmt das. Anders als FerretSharp läuft RepoBoard oft nur im Infobereich (ADR 0006): Ein Hinweis im Fenster allein würde dort nicht gesehen.

## Entscheidung

- **Velopack 1.2.161** (Paket in `RepoBoard.App`, `vpk` im Tool-Manifest, dieselbe Version wie FerretSharp): `Setup.exe` installiert pro Benutzer nach `%LocalAppData%\RepoBoard` (keine Adminrechte), dazu ein Portable-Zip, das sich ebenfalls aktualisiert, volle und Delta-Pakete und der Feed `releases.win.json`. Unsigniert wie FerretSharp: SmartScreen warnt einmal.
- **Einstieg:** `Program.Main` ruft zuerst `VelopackApp.Build().SetAutoApplyOnStartup(false).Run()` – Velopacks Hooks starten die App mit eigenen Argumenten und enden dort; ohne `SetAutoApplyOnStartup(false)` würde ein Download beim nächsten Start ungefragt installiert. Vor dem Deinstallieren entfernt ein Hook jeden Autostart-Eintrag dieses Programms (`Autostart.Starts`), auch die anderer Datenordner – sonst startet Windows bei jeder Anmeldung ein Programm, das es nicht mehr gibt. Ein Update behält den Pfad (`current\RepoBoard.exe`), der Eintrag bleibt gültig.
- **Prüfen und melden** (`UI/State/UpdateState`, aus FerretSharp mit allen Nachträgen; Schnittstelle `IAppUpdater`, Implementierung `VelopackUpdater` im Host): Prüfung beim Start (`AppSettings.CheckForUpdates`, Standard an) und während RepoBoard läuft (`UpdateCheckHours`: 0, 1, 4 (Standard), 24; alle 5 min wird nachgesehen, ob das Intervall seit der letzten Prüfung um ist), „Jetzt prüfen“, Zeitlimit 30 s. Eine gescheiterte Prüfung ist nur ein Hinweis in den Einstellungen. Ist ein Update bekannt, prüft der Hintergrund still weiter (eine neuere Version ersetzt es), und „Herunterladen“ prüft vorher noch einmal. Nicht installiert (Build, `dotnet run`): keine Prüfung, die Einstellungen sagen warum.
- **Anzeige:** Statt FerretSharps Statusleiste ein Knopf in der Kopfzeile („Update 0.2.0 verfügbar“, Fortschritt, „Neu starten für 0.2.0“, „Update fehlgeschlagen“), der Dialog mit den Notizen (`ReleaseNotes`: der CHANGELOG-Abschnitt als einfache Blöcke, kein HTML, keine Bilder – nichts aus dem Internet wird geladen) und ein Abschnitt „Updates“ im Einstellungsmenü.
- **Benachrichtigung:** Eine neue Version meldet `UpdateState.Announced` einmal; gemerkt in `AppSettings.UpdateNotified`, damit ein Start mit Windows nicht jeden Morgen dieselbe Version meldet. Nur neuere Versionen als die gemerkte. Der Host zeigt sie als Balloon-Tip wie die Auto-Sync-Meldungen (ADR 0006): nicht über dem sichtbaren, aktiven Fenster (dort steht der Knopf) und nicht, wenn Benachrichtigungen aus sind; gemerkt wird die Version trotzdem. Ein Klick aufs Popup öffnet das Fenster mit dem Dialog.
- **Neustart:** zwei Klicks wie in FerretSharp – „Herunterladen“, dann „Jetzt neu starten“. RepoBoard hat nichts Ungesichertes zu erfragen (FerretSharps `ExitGuard` entfällt): `AppExit.Request` beendet die App wie „Beenden“ im Infobereich; erst nach dem Stoppen des Hosts (`App.OnExit`) startet `WaitExitThenApplyUpdates` den Updater, der auf das Prozessende wartet, installiert und die neue Version mit denselben Argumenten startet (`CommandLine.Restart`: volle Pfade, ohne `--minimized` und `--exit` – der Neustart folgt einem Klick, das Fenster soll kommen).
- **Release-Workflow** (`.github/workflows/release.yml`, auf Tag `v*` oder von Hand): Version gegen `Directory.Build.props`, Tests, `dotnet publish` (self-contained, win-x64), Notizen aus dem CHANGELOG-Abschnitt (`changes.md` für den Dialog, `notes.md` mit Download-Hinweisen für GitHub), `vpk download github` (Delta zum letzten Release), `vpk pack` (Pack-Id `RepoBoard`, `.pdb` bleiben drin), `vpk upload github` als Entwurf, dann `gh release edit` veröffentlicht. Actions per Commit-SHA gepinnt, Token nur in den vpk/gh-Schritten.
- **Testen ohne GitHub:** `--update-source=<Ordner>` liest einen lokalen Feed (`SimpleFileSource`) – nur für Tests, im README nicht beworben.

## Konsequenzen

- Das erste Release nach diesem Paket hat nur volle Pakete (kein Velopack-Vorgänger); danach Deltas. Notizen übersprungener Versionen kennt nur eine Setup-Installation (lokales volles Paket); das Portable-Zip zeigt nur die Notizen der Zielversion und verweist auf GitHub.
- Ohne Token gelten 60 Anfragen je Stunde und Adresse – mit einer Prüfung je Start und alle paar Stunden weit darunter.
- Wer das GitHub-Konto übernimmt, kann ein Update ausliefern (unsigniert). Signieren steht wie in FerretSharp im Backlog.
- Eine Benachrichtigung ist ein Balloon-Tip: im Benachrichtigungscenter wirkt ein Klick nicht (ADR 0006). Ein neuer Balloon-Tip schließt das Popup des vorigen (gemessen: 17 ms) – ein Klick trifft immer die zuletzt gezeigte Meldung, aber eine Auto-Sync-Meldung kurz vor der Update-Meldung ist dann nur noch im Benachrichtigungscenter.
- Eine gescheiterte Prüfung (beim Start mit Windows oft noch kein Netz) wird nach 15 min wiederholt, bis eine antwortet, auch bei „Nie“ – nicht öfter, ein Rate-Limit von GitHub würde sonst schlimmer (Review WP-10).
- Ein zweites Profil (`--data-dir`) aus derselben Installation läuft aus demselben `current\`: Velopacks Updater beendet vermutlich alle Prozesse dort, bevor er `current` austauscht – die zweite Instanz endet dann ohne Aufräumen (Symbol bleibt stehen bis zur Maus, kein Neustart; Daten gehen nicht verloren, `config.json` wird atomar geschrieben). Nicht geprüft (Review WP-10).
